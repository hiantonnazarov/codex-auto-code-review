# Codex Auto Code Review

Автоматическое независимое ревью кода через нативные hooks Codex. Источник изменений — **только успешные вызовы `PostToolUse` для `apply_patch`**. App Server, Git diff/status/HEAD, shell-команды и снимки проекта для получения изменений не используются.

## Установка на Windows

PowerShell в корне локального репозитория (где находится `pyproject.toml`):

```powershell
py -m pip install --user -e .
py -m codex_auto_review.cli install
py -m codex_auto_review.cli doctor
```

Если активировано виртуальное окружение, уберите `--user`. Затем перезапустите Codex и разрешите новые хуки через `/hooks`, если команда доступна. Установка сохраняет сторонние записи в `~/.codex/hooks.json`.

Публичный CLI:
- `install` — зарегистрировать хуки;
- `uninstall` — удалить только свои хуки;
- `doctor` — проверить регистрацию и факт получения событий.

Внутренний `hook` запускается самим Codex. В обычной работе ручные команды не требуются.

## Архитектура

```text
UserPromptSubmit  → сохранить полный исходный запрос и идентификаторы хода
PostToolUse        → matcher "^apply_patch$", проверка успеха инструмента,
                     сохранить операции и файлы по session_id + turn_id
Stop               → фильтр "только код" + exclude_globs + пороги
                   → независимый codex exec --sandbox read-only
                   → проверка исходного запроса и патчей
                   → структурированные findings P0-P3 и отчёт
                   → при ошибках Stop decision:block, исправления основным Codex
                   → до 3 раундов
```

Сохраняются именно операции успешных `apply_patch`. Повторные события одного `tool_use_id` не дублируются. Последовательные патчи одного файла агрегируются, но **это не net diff конечного файла**. При пропущенном или непонятном ответе инструмента ревью не считается успешным.

### Политика выбора изменений

- Только исходный код: расширения из `CODE_SUFFIXES`, `Dockerfile`, `Makefile`, `Containerfile`.
- Документация и другие типы файлов пропускаются.
- Исключения только через `exclude_globs`; никаких выделенных каталогов `auth`/`security`.
- Режим `significant`: 30 изменённых строк ИЛИ два файла; удаление/переименование кода проверяется независимо от числа строк. Режим `all`: любой подтверждённый патч кода.
- Независимый reviewer получает **полный первоначальный запрос** (а не замечания предыдущего reviewer) и патчи своего хода; основной агент исправляет ошибки по результатам review.

## Ограничения

1. Изменения через Bash, PowerShell, Python-скрипты, другие инструменты и внешние программы **намеренно не отслеживаются**. Если других успешных `apply_patch` не было, ревью не запустится.
2. Codex может не доставить `PostToolUse` на некоторых специализированных путях. Регистрация хуков не является гарантией доставки. На Windows Desktop обязательно выполнить smoke test. `doctor` показывает время последнего события, но не доказывает полноту.
3. Списки патчей разделены по `session_id` / `turn_id`, однако если несколько агентов одновременно редактировали один файл, текущий файл на диске может содержать чужие правки. Reviewer ограничен переданными патчами.
4. Успешный `apply_patch` может быть no-op. Неудачная операция может оставить частично применённые изменения; такие случаи не покрываются без других источников, которые здесь намеренно удалены.
5. Codex субагенты могут наследовать `session_id` родителя; одинаковый `turn_id` может означать недостаточную изоляцию субагентов.
6. Не относящиеся к ходу committed/staged изменения не попадают в область ревью. Но патчи, закоммиченные в рамках самого хода, продолжают проверяться, поскольку Git-проверок нет.
7. По умолчанию `fail_open = false`: техническая ошибка прерывает завершение текущей проверки с явным сообщением, а не объявляет успех. Если установить `fail_open = true`, Codex сможет завершить ход при ошибке, но результат не считается `passed`.

## Конфигурация и проверка

Глобальный `~/.codex-auto-code-review/config.toml`; в проекте `config.toml` с таблицей `[review]`. По умолчанию reviewer запускается с read-only sandbox и JSON-схемой. Настройки приведены в [config.toml](config.toml), спецификация — [requirements.md](requirements.md).

```powershell
py -m pip install -e . pytest
py -m pytest -q
```

Unit-тесты не заменяют реальный пробный запуск в Codex Desktop. Официальные источники: [Codex Hooks](https://developers.openai.com/codex/hooks/), [Apply Patch](https://developers.openai.com/api/docs/guides/tools-apply-patch).
