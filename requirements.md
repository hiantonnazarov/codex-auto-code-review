# Codex Auto Code Review — требования и архитектура

**Режим:** глобальные Codex hooks, единственный источник изменений — `PostToolUse(apply_patch)`.

## Цель

Пользователь устанавливает пакет на Windows один раз. После хода Codex с существенными изменениями исходного кода запускается **отдельный read-only Codex reviewer**. Он получает оригинальное пользовательское задание, успешно применённые патчи **этого хода**, читает необходимый контекст кода и возвращает замечания. Основной Codex исправляет ошибки, пока ревью не пройдено либо не достигнут лимит.

## Архитектура

1. `UserPromptSubmit`: сохранять полный оригинальный запрос, `session_id`, `turn_id`. Продолжения от `Stop` не должны переписывать исходное задание.
2. `PostToolUse`, только matcher `^apply_patch$`: сохранять операции инструмента, когда результат подтверждает полный успех; дедуплицировать `tool_use_id`. Не принимать события Bash, MCP, App Server, внешних файловых наблюдателей или Git как источник изменений.
3. Разбирать операции `*** Add File`, `*** Update File`, `*** Delete File`, `*** Move to`. Проверять все пути на выход за границу репозитория; не принимать `.git` и ссылки за пределы каталога.
4. Хранить патчи по `repo + session_id + turn_id`. Несколько операций по одному пути объединять в хронологической последовательности наблюдения. Операции не являются итоговым diff файла. Незнакомый формат успешного ответа означает ошибку захвата, а не успех ревью.
5. `Stop`: фильтровать пути по программным расширениям и `exclude_globs`. Режим `significant`: не менее 30 строк +/- ИЛИ не менее 2 файлов; удаление и переименование одного файла кода обязательно проверяются. Режим `all`: любые подтверждённые изменения кода. Игнорировать документацию.
6. Reviewer: отдельный `codex exec --sandbox read-only`, строгая JSON-схема, исходное задание + патчи + доступ к окружающему коду. Не делать Git diff и не захватывать дополнительные файлы как изменённые.
7. Findings: P0–P3, файл, строка, объяснение, уверенность. Проверять допустимый путь и JSON; P0–P2 при confidence ≥0.65 блокируют по умолчанию.
8. При blocking findings `Stop` возвращает `decision:"block"`, чтобы исправления делал родительский агент. Сохранять исходную задачу и счётчик раундов при продолжении. По умолчанию максимум 3 проверки; превышение лимита никогда не считать пройденным review.
9. Межпроцессная блокировка, атомарные файлы состояния, SHA-256 hash набора патчей для дедупликации, JSON-отчёты с источником, временем, задачей, результатом и ошибками.
10. Установщик добавляет `UserPromptSubmit`, `PostToolUse` (matcher `^apply_patch$`), `Stop`, сохраняет прочие хуки. Пользовательский CLI: `install`, `uninstall`, `doctor`. Другие публичные CLI-команды удалить.
11. Неиспользуемые App Server `appserver.py`, `proxy.py`, их тесты, ручной review, snapshot/Git diff код и упоминания удалить.

## Границы гарантий

- Вызов reviewer гарантирует только собственный код на условии поступления нужных событий. Доставка хуков Codex Desktop должна проверяться на целевой версии.
- Изменения через shell, скрипты, Git, MCP, IDE и другие инструменты не охватываются. Неизвестный ответ инструмента => ошибка scope; частично применённый патч с ошибкой может быть упущен.
- Отмеченные патчи не доказывают итоговое net-изменение файлов, факт uncommitted или исключительное авторство текущего содержимого файла.
- Чужие сессии не участвуют в наборе событий, если у них отдельные `session_id`/`turn_id`. Субагенты иногда наследуют сессию родителя. Изменения одного общего файла, видимые через контекстное чтение, могут включать чужие фрагменты.
- После `Stop`-continuation создаётся новый ход: сохранять оригинальную задачу и нерешённые замечания, но получать отдельные новые патчи. Не утверждать, что патчи предыдущего хода равны итоговому состоянию нового хода.
- По умолчанию `fail_open = false`: техническая ошибка должна останавливать завершение хода без `passed`. При ручном включении `fail_open = true` ход допускается завершить с явным предупреждением.

## Приёмочные тесты

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| AC-01 | Установка хука дважды | Ровно один `PostToolUse(^apply_patch$)`, остальные хуки сохранены |
| AC-02 | Успешный `apply_patch` меняет два файла кода | Оба файла переданы независимому reviewer |
| AC-03 | `apply_patch` изменил только README | Ноль вызовов reviewer |
| AC-04 | Неуспешный apply_patch | Не засчитывается как успешная операция |
| AC-05 | Непонятный ответ/патч | Явная ошибка захвата |
| AC-06 | Два параллельных `session_id` | Отдельные списки и патчи |
| AC-07 | Путь `../`, вне репозитория, `.git` | Отклоняется |
| AC-08 | Несколько операций одного файла, повторы `tool_use_id` | Объединение операций, без дубликатов |
| AC-09 | Есть чужие committed/staged изменения | Не добавлять их в scope |
| AC-10 | Reviewer P1 | Blocking feedback, основной агент исправляет |
| AC-11 | Reviewer без ошибок | `passed` и JSON-отчёт |
| AC-12 | Повторный Stop без новых патчей | Не запускать reviewer повторно |
| AC-13 | Продолжение нового хода | Сохранён оригинальный запрос и общий лимит раундов |
| AC-14 | Windows/Linux/macOS | Проходят тесты и проверка синтаксиса |
| AC-15 | Windows Codex Desktop | Ручной smoke-test доставки hooks (не заменяется CI) |

Официальный контракт: [Codex Hooks](https://developers.openai.com/codex/hooks/).
