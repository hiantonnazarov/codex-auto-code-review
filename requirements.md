# Codex Auto Code Review — требования и архитектура

**Статус:** актуальная спецификация. **Источник diff:** только события Codex App Server.  
**Реализация:** Python 3.11+, Codex CLI для независимого reviewer, обычные Codex hooks для gate.  
**Платформы:** Windows без WSL, Linux, macOS.

## 1. Цель

Пользователь работает с Codex как обычно. После хода с существенными изменениями **кода** запускается отдельное read-only ревью, замечания возвращаются основному Codex через `Stop` при поддержке хоста, затем исправления могут быть повторно проверены. Незначительные правки и документация не вызывают LLM.

**Запреты архитектуры:** нельзя собирать diff из Git, Git HEAD/index/status/log, команд инструментов, истории сессий, текста LLM. Нельзя собирать или сверять изменения параллельных сессий. Нельзя добавлять worktrees либо собственное управление Git.

**Единственное исключение:** поиск корня репозитория по наличию `.git` для определения расположения локальной конфигурации. Эта операция не ищет изменения файлов.

## 2. Получение изменений

| ID | Требование |
|---|---|
| FR-01 | Источником изменённых файлов/патчей служит исключительно `turn/diff/updated` App Server, содержащее `threadId`, `turnId` и полный актуальный `diff`. |
| FR-02 | `turn/started` служит сигналом, что клиент действительно передаёт поток, `turn/completed` — статусом завершения хода; ни то ни другое не используется как альтернативный источник diff. |
| FR-03 | Каждое новое `turn/diff/updated` **заменяет**, а не дополняет предыдущий diff того же хода. Состояние хранится отдельно по `threadId + turnId`. |
| FR-04 | При отсутствии подключённого App Server и событий запрещены скрытый Git fallback, «успешное ревью» и повторное использование старого хода. |
| FR-05 | Старые коммиты, staged/unstaged изменения и новые файлы, отсутствующие в поступившем App Server diff, **никогда не добавляются в ревью**. |
| FR-06 | Дополнительные Git-проверки для исключения коммитов, определения авторства, параллельных изменений и полноты diff **не выполняются**. |
| FR-07 | Не разрешается автоматически запускать новый отдельный App Server и выдавать его diff за изменения текущего чата: требуется получить события именно активного экземпляра. |

**Важная граница FR-05:** невозможно гарантировать исключение фрагментов, закоммиченных *в рамках того же хода*, поскольку `turn/diff/updated` не предоставляет признак committed/uncommitted. Без Git-сверки это неустранимо. Если App Server пропустил правку (например, скриптовую), её нельзя восполнить без другого источника. Это сознательное ограничение спецификации.

## 3. Подключение App Server

**FR-08.** Реализовать прозрачный `appserver-proxy`: хост при наличии такой настройки запускает его вместо собственного `codex app-server`, proxy запускает реальный `codex app-server --listen stdio://`, передаёт JSON-RPC сообщения без изменения и сохраняет только три типа событий ``turn/started`, ``turn/diff/updated`, ``turn/completed`.

**FR-09.** Для интеграций с собственным клиентом реализовать приём потоковых исходных App Server notifications через `appserver-ingest` (JSONL stdin). Это другой транспорт **того же источника**, а не альтернатива App Server.

**FR-10.** Установка `Stop`/`UserPromptSubmit` хуков безопасна и сохраняет сторонние записи. **Хуки сами не умеют подписываться на события чужого App Server**. Запуск через proxy требуется настроить на стороне клиента; не обещать автоматическое покрытие обычного Codex Desktop без подтверждённой поддержки подключения.

## 4. Политика значимых изменений

**FR-11.** Проверяются только исходники: программные расширения из `CODE_SUFFIXES` плюс названия файлов `Dockerfile`, `Makefile`, `Containerfile`. Документация (`.md`, `.rst`, `.txt` и другие некодовые файлы), JSON/TOML/YAML-конфигурации, изображения и другие нераспознанные типы не анализируются по умолчанию.

**FR-12.** Путь фильтруется единственным набором настраиваемых масок `exclude_globs`; `include_globs` и `critical_globs` отсутствуют. Ни одна папка (`auth`, `security`, `api`, `payments` и т. п.) не имеет специального приоритета.

**FR-13.** Режимы:
- `significant` (по умолчанию): не менее `min_changed_lines = 30` суммарно добавлений/удалений исходного кода **или** минимум `min_changed_files = 2` разных файлов кода;
- `all`: любое ненулевое изменение выбранных файлов кода.

**FR-14.** Фильтрация и пороги определяются детерминированно, до вызова LLM. Ошибка формата diff не маскируется отсутствием изменений.

## 5. Независимый reviewer

**FR-15.** Отдельный `codex exec` со свежим контекстом и `--sandbox read-only`; не имеет права редактировать код.

**FR-16.** Передавать reviewer только отфильтрованный исходный App Server diff, пути, исходный пользовательский запрос и возможность читать окружающий код; не вызывать Git diff и не сканировать остальные изменения.

**FR-17.** Проверять корректность, регрессии, интерфейсы, пограничные случаи, надёжность, безопасность и тесты, способные обнаруживать ошибочную реализацию. Косметику не блокировать.

**FR-18.** Reviewer возвращает строгий JSON: `summary`, массив `findings`. Каждое замечание содержит `priority` (P0–P3), `file`, `line`, `title`, `explanation`, `confidence` (0..1). Проверять схему, разрешённые файлы и существующие строки локального кода.

**FR-19.** P0–P2 при `confidence >= 0.65` блокируют по умолчанию. При ошибке reviewer не возвращать `passed`.

**FR-20.** Для большого diff разделять на фрагменты без молчаливой обрезки и запускать отдельный интеграционный проход при нескольких чанках. Количество чанков/таймауты ограничиваются.

## 6. Цикл и состояние

**FR-21.** `UserPromptSubmit` сохраняет исходный запрос и `turn_id`, не выполняя Git snapshot. `Stop` использует только сохранённый diff с совпадающими `session_id/threadId` и `turn_id`.

**FR-22.** При блокирующих замечаниях вернуть `decision:"block"`, если хост умеет продолжать ход. Исправления вносит только основной агент.

**FR-23.** Повторный Stop с тем же digest App Server diff не вызывает LLM повторно. При новом diff выполняется новая проверка. Подтверждённый `passed` относится строго к digest проверенного diff, а не всему рабочему каталогу.

**FR-24.** Не более трёх раундов по умолчанию. Лимит и неустранённые замечания всегда видимы и не считаются успехом.

**FR-25.** Сохранение состояния и отчётов атомарно, межпроцессные блокировки не допускают повторных конкурирующих ревью одной сессии. Ошибка передачи событий или повторной проверки не превращается в `passed`.

**FR-26.** `doctor`, `status`, `config`, `install`, `uninstall`, ручной `review --session THREAD_ID --turn TURN_ID --cwd .`. Ручной `review` использует только ранее полученный App Server diff — никогда Git HEAD.

**FR-27.** Отчёт содержит репозиторий, идентификаторы сессии и хода, SHA-256 проверенного **App Server diff**, время, статус, номер раунда, замечания и ошибки. Хранится вне репозитория по умолчанию.

## 7. Приёмочные тесты

| № | Сценарий | Ожидаемый результат |
|---|---|---|
| AC-01 | App Server diff с одной небольшой правкой `auth/login.py` | Не запускать review в режиме significant; специальных правил нет |
| AC-02 | App Server diff с двумя файлами кода или 30 строками | Один независимый reviewer |
| AC-03 | Изменена только документация/README | Ноль LLM-вызовов |
| AC-04 | Diff содержит код в масках `exclude_globs` | Исключить соответствующие файлы |
| AC-05 | До/во время хода существуют committed и staged файлы вне diff события | Они не добавляются в область ревью |
| AC-06 | Два сообщения `turn/diff/updated` одного хода | Использовать только последнее агрегированное значение |
| AC-07 | Несколько потоков с разными `threadId` | Изоляция их сохранённых событий |
| AC-08 | Есть только `Stop`, нет событий App Server | Явная ошибка, нет Git fallback и нет ложного `passed` |
| AC-09 | `turn/completed` с `failed` или `interrupted` | Не принимать review как успешное |
| AC-10 | Codex возвращает P1 выше порога | Stop блокирует с причиной |
| AC-11 | Ревьюер возвращает P3 или пустые findings | `passed` и JSON-отчёт |
| AC-12 | App Server diff изменился во время reviewer | Старый результат не принимать |
| AC-13 | Повторный Stop на идентичном diff | Нет повторного платного вызова |
| AC-14 | Неверный JSON/таймаут или превышенный лимит чанков | Явная ошибка |
| AC-15 | Proxy получает JSON-RPC поток | Весь поток передаётся байт-в-байт, события сохраняются |
| AC-16 | Windows/Linux/macOS и Python 3.11+ | Пройдены интеграционные/регрессионные тесты |
| AC-17 | Хост не поддерживает замену App Server или доставку Stop | В документации указан фактический предел автоматизации |

Юнит-тесты не доказывают качество LLM-оценок; отдельно требуется smoke test с работающим клиентом App Server и авторизованным Codex.
